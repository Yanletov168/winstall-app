# winstall

[English](README.md) | Русский

winstall — лёгкий нативный Windows GUI для Windows Package Manager (winget).
Остаётся тонким фронтендом: все операции с пакетами идут через системный
winget, ничего не дублируется. Сделан прежде всего для Windows 10, включая
21H2; Windows 11 и новее поддерживаются за счёт совместимости.

## Возможности

- Одно окно-список: установленные программы, обновляемые — жирным наверху.
- Смысл галочки: обновляемое — обновить (↑), свежее — удалить (×), найденное
  в поиске — установить (+). Колонка-значок всегда показывает действие.
- Поиск по всей базе winget; три вида: установленные, обновления, поиск.
- Нативные имена и иконки из реестра Uninstall.
- Панель с издателем и описанием из `winget show`.
- Обновление всего в один клик; экспорт и импорт списка пакетов.
- Предложение переустановки, когда winget отказывается обновлять из-за смены
  технологии установщика (`0x8A15008E`).
- Опциональная проверка обновлений (автозапуск при входе + задача на
  пробуждение) с баллуном только о количестве; клик открывает winstall.
- Локализация интерфейса через `locales/*.json` (русский, английский);
  новый язык — один файл, выбор в меню ☰.

## Установка

### Установщик

`Setup-winstall-x64.exe`, `Setup-winstall-x86.exe`, `Setup-winstall-arm64.exe`
из [Releases](https://github.com/Yanletov168/winstall-app/releases).
Установка per-user, без UAC для самой программы.

В конце установки проверяется системный WinGet. Если он есть — ничего больше
не происходит. Если его нет — установщик явно спрашивает согласия, затем
скачивает официальный App Installer с серверов Microsoft и ставит его;
этот шаг показывает собственный UAC-запрос. Ошибки показываются, а не
прячутся. Без WinGet программа работать не может: собственный пакетный
менеджер она не поставляет (см. Совместимость).

### Portable

`winstall-portable.zip` из
[Releases](https://github.com/Yanletov168/winstall-app/releases):

```text
winstall-x86.exe
winstall-x64.exe
winstall-arm64.exe
locales/
  en.json
  ru.json
```

Выбор exe под машину, установка не нужна. Все три бинарника используют общий
`locales/` рядом с ними; запуск без него — встроенный английский. Крошечная
сборка под Framework для машин без .NET 8 публикуется отдельно как
`winstall-portable-net48.zip` (нужен встроенный .NET Framework 4.8).

## Совместимость

Основная цель: **Windows 10 21H2 и новее** (x64/x86). Windows 11 и новее
поддерживаются за счёт совместимости, а не как основная платформа. Сборки
ARM64 — для Windows 10/11 на ARM64. Установщики отказываются ставиться ниже
Windows 10. Сборки .NET 8 self-contained везут рантайм с собой; сборка net48
использует встроенный .NET Framework 4.8.

Самому WinGet нужен Windows 10 1809 или новее.

### Поведение portable / fallback WinGet

Portable-сборкам нужен системный WinGet. При первом запуске winstall
проверяет его один раз (PATH плюс алиас App Installer) и запоминает рабочее
место в `options.ini` (`winget_path`, запасной путь — AppData). Отсутствие
проверяется заново при каждом запуске, так что позже установленный App
Installer подхватится сам, а упавший в рантайме backend сбрасывает кэш и
определяется повторно. Если backend не найден, программа предлагает
поставить официальный App Installer (то же предложение, что в установщике)
и закрывается в любом случае: Да открывает страницу загрузки, Нет просто
закрывает. Отказ означает отсутствие программы — без backend winstall
не работает.

Bundled-fallback'а осознанно нет: один `winget.exe` неработоспособен — ему
нужен зарегистрированный пакет App Installer (MSIX-identity и COM-сервер),
а запуск вне официальной дистрибуции Microsoft не поддерживает. Фальшивый
fallback не делаем; поддерживаемый путь получения WinGet на пустой машине —
скачивание и регистрация официального App Installer установщиком (см. выше).

## Использование

- Галочка у обновляемого — обновить, у свежего — удалить (с подтверждением),
  у найденного в поиске — установить. Затем `▶ Выполнить`.
- `Обновить всё (N)` — один вызов `winget upgrade --all --silent`.
- В меню ☰: экспорт/импорт, массовый выбор, автопроверка, язык, логи winget.
- `winstall.exe --check-updates` — тихий режим для проверки: без окна,
  баллун при обновлениях, молчаливый выход иначе.
- Настройки живут в `options.ini` рядом с exe (язык, кэш backend, папка
  логов установщиков, флаги по глаголам). Через меню ☰ меняются язык и папка
  логов; запись backend ведётся автоматически.
- Флаги политики централизованы, по набору на глагол, скрытых дефолтов нет:
  `upd_flags` (upgrade), `add_flags` (install), `rem_flags` (uninstall).
  Пример: `upd_flags = --accept-package-agreements --accept-source-agreements --disable-interactivity --silent --include-unknown`.
  У read-only запросов фиксированная неинтерактивная пара, чтобы свежие машины
  не висли на промптах.

## Сборка из исходников

.NET SDK 8 или новее. Рантайм на целевую машину ставить не надо.

```bat
dotnet build winstall.csproj -c Release
```

Self-contained публикация под архитектуру:

```bat
dotnet publish winstall.csproj -c Release -f net8.0-windows -r win-x64 --self-contained true /p:PublishSingleFile=true
```

Установщики требуют [Inno Setup 6](https://jrsoftware.org/isinfo.php):

```bat
iscc /DMyArch=x64 /DMyVersion=1.1.0 /DSrcDir=..\dist\win-x64 /DOutDir=..\dist-installer installer\winstall.iss
```

Проверки (парсинг вывода winget, локализации, цикл задачи планировщика, кэш backend):

```bat
dotnet run --project tests\parsetest\parsetest.csproj
```

## Технические заметки

- winget говорит таблицами; колонки делятся по 2+ пробелам. У `winget list`
  два формата (с колонкой Available и без) — парсятся оба.
- Программы, поставленные мимо winget, видны как ARP-строки без источника;
  связываются с базой по точному имени, обновляются по связанному id.
- У `uninstall` нет `--accept-package-agreements`; его передача заставляет
  winget печатать справку и выходить с `0x8A150002`.
- Вывод schtasks читается в OEM-кодировке консоли; кавычки `/TR`
  экранируются на уровне argv, чтобы выживали пути с пробелами.
- Продвинутые могут зафиксировать backend переменной окружения
  `WINSTALL_WINGET` (путь — или `none` для принудительного пути «нет backend»).
- Автопроверка специально без админских прав: вход через ключ Run в HKCU,
  пробуждение через задачу ONEVENT (Power-Troubleshooter ID 1).
  ONLOGON-триггеры и импорт XML требуют elevation и не используются.
